# Jev Inbox

問い合わせを、次の一歩へ。TypeSafe AIの **Jev** を使って、日本語の問い合わせを分類・優先度・返信要否に仕分ける、ローカル専用のワークスペースです。

## まずはデモで使う

必要なものは **Node.js 22.12以上（24 LTS推奨）** とnpmです。

```sh
npm ci
npm run dev
```

[http://127.0.0.1:5173](http://127.0.0.1:5173) を開きます。APIキーは不要です。8件の架空サンプルと、ローカルのルールによるデモ判定を用意しています。

1. 「未仕分けを一括仕分け」でサンプルを処理します。
2. 問い合わせを選ぶと、本文、分類、確信度、優先度、返信が必要な確率を確認できます。
3. 「要確認」の問い合わせを「確認・修正」で確定します。
4. 対応を終えたら「対応済みに」で記録します。

新規追加・編集・削除、検索、分類フィルター、優先度順の並び替え、履歴、JSONバックアップ、CSV出力にも対応しています。問い合わせは最大200件、本文は6,000文字まで。一括処理は未仕分けの先頭20件までを順次実行し、途中で中止できます。

> デモ判定はJevの推論結果ではありません。キーワードルールによるシミュレーションで、速度・精度・確信度はモデルの性能評価に使えません。デモモードではTypeSafeへの送信はありません。

## 本物のJevに接続する

[TypeSafe Console](https://console.typesafe.ai) でAPIキーを取得し、アプリの「ルールと接続」で入力して「Jevに接続」を選びます。設定保存だけではAPIを呼びません。仕分けボタンを押すとAPI利用料金が発生します。

ブラウザから入力したキーはメモリ内だけに保持し、localStorage・JSON・CSVには保存しません。再読み込みするとキーは消え、デモモードに戻ります。

任意でサーバー側に設定することもできます。

```sh
# .env.example を .env.local にコピーし、TYPESAFE_API_KEY を設定
# Windows PowerShell:
Copy-Item .env.example .env.local
```

```dotenv
TYPESAFE_API_KEY=your-key-here
PORT=8787
```

サーバーを再起動してください。`.env.local` はGit管理から除外しています。`VITE_` 接頭辞にキーを入れないでください。画面で入力したキーがあればサーバーのキーより優先します。

公式 [`@typesafe-ai/sdk`](https://github.com/typesafe-ai/typesafe-sdk-js) をサーバーから呼び出し、`POST https://api.typesafe.ai/v1/systemone` の `jev-latest` を使用します。一件につき3問を一回のリクエストにまとめます。

| Jevの型 | 判定                                                             | アプリでの使い方                                   |
| ------- | ---------------------------------------------------------------- | -------------------------------------------------- |
| Choice  | 不具合・技術 / 請求・契約 / アカウント / 機能リクエスト / その他 | 担当チームを提案                                   |
| Score   | 緊急度の期待値（0〜3。小数あり）                                 | 0.5未満=低、1.5未満=通常、2.5未満=高、2.5以上=緊急 |
| Noul    | 返信が必要な確率（0〜1）                                         | 確率をそのまま表示。曖昧なら確認対象               |

分類と緊急度の**確信度**は、それぞれモデルの応答から取得します。確率分布とは別の値です。

## 人に確認を回すルール

次のいずれかなら「要確認」にします。

- 分類または緊急度の確信度が設定値未満（初期値80%、設定範囲50〜99%）
- 分類が「その他」
- 緊急度が2.5以上
- 返信が必要な確率が35%超〜65%未満

基準を変えると、保存済みの未確認案件にも即時反映します。人が確認済みの結果や対応済み状態は維持します。モデルの判定は誤ることがあるため、確信度は正しさの保証として扱わないでください。

内容を編集した場合は古い判断の流用を避けるため、判定・人の確認・対応済み状態をリセットし、編集履歴を残します。人の確認結果がある案件の再仕分けも、内容の編集によるリセットが必要です。

## 保存とプライバシー

- 問い合わせ・判定・履歴は、このブラウザの `localStorage` に保存します。サーバーにデータベースはありません。
- 実接続時は、**件名・本文・チャネル**をローカルサーバー経由でTypeSafeに送ります。差出人欄は送りませんが、本文に書かれた個人情報は送信対象です。
- 返信送信、外部サービスへの割り当て、Slack・メール・CRMとの連携は行いません。
- JSONは全件のバックアップです。読み込みは追加方式で、同じIDはスキップし、現在の確信度設定は維持します。新しいデータを上書きしたい場合は、元の問い合わせを削除してから読み込んでください。
- CSVは集計用です。Excel数式として扱われる可能性のある先頭文字をエスケープします。再読み込みにはJSONを使ってください。
- 保存が壊れている場合は自動で上書きしません。設定の「保存領域をそのまま書き出す」で元データを保管できます。保存容量不足などの場合も警告を出します。
- このアプリは単一ユーザーのローカル利用向けです。共有PCでは保存データに他の利用者がアクセスできる場合があります。

## ビルドして起動

```sh
npm run build
npm start
```

[http://127.0.0.1:8787](http://127.0.0.1:8787) を開きます。サーバーはループバックアドレスにのみバインドします。認証付きの共有サービスとして設計していないため、リバースプロキシやトンネルを使った公開は想定していません。

開発時はWeb=5173、API=8787の構成です。`PORT` を変更するときは、開発用の `vite.config.ts` のプロキシ設定も合わせてください。本番ビルドではWebとAPIを同一ポートで提供します。

## テスト

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

単体・APIテストは仕分けルール、境界値、公式SDKの通信形式、入力検証、エラー時の結果保持、キー非露出、外部Origin/Hostの拒否、呼び出し上限を確認します。ブラウザテストはデスクトップ/モバイル幅で追加・仕分け・確認・編集・保存・入出力を確認します。

APIは15秒タイムアウト、自動リトライなし、最大2件同時、実リクエスト30件/分までです。実接続の失敗をデモに置き換えません。応答はZodで検証し、不正なラベル・数値・確率分布は保存しません。モデルのプロンプトインジェクション耐性や日本語精度を保証するものではありません。

CIにはGitHub Actionsを設定しています。秘密情報なしで型検査、単体/APIテスト、ビルド、ブラウザテストが動きます。**APIキー未設定のため、開発時に実Jevへの推論リクエストは行っていません。** SDKの検証は模擬応答による契約テストです。

WindowsではPlaywrightの依存DLL検査ツール `winldd/PrintDeps.exe` がセキュリティソフトに検知される場合があります。このツールはアプリの通常利用には不要です。ブロックを解除せず、ブラウザテストはGitHub ActionsのLinux環境で実行できます。

## 構成

```text
src/                Reactの日本語UI・ローカル保存
shared/domain.ts    型・検証・仕分けルール・CSV
shared/demo.ts      架空サンプルと明示的なデモ判定
server/jev.ts       公式SDKによるJevへの問い合わせ
server/app.ts       ローカルAPI・入力/Origin/Host検証
tests/              単体・API・SDK契約テスト
tests/e2e/          Playwrightの操作テスト
```

React / TypeScript / Vite / Express / Zod / Lucide Icons。直接依存はバージョンを固定し、`package-lock.json` を同梱しています。

参考: [TypeSafeの概要](https://docs.typesafe.ai/introduction)、[確信度](https://docs.typesafe.ai/confidence)、[APIリファレンス](https://docs.typesafe.ai/api)。TypeSafe AIの公式製品ではなく、独立したサンプルアプリです。
